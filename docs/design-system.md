# 幻画 AI 液态玻璃设计规范

> 版本：1.0  
> 更新日期：2026-07-15  
> 适用范围：Vue 客户端、Tauri 桌面端和后续新增的业务界面

## 1. 设计定位

幻画 AI 是面向高频图像创作的桌面工作台。界面采用“深色液态玻璃控制台”风格：透明但不轻浮，精致但不牺牲信息密度。视觉应服务于提示词输入、参数比较、结果检查和重复生成，不能演变成营销页或装饰性展厅。

核心感受：

- **安静的专业感**：背景退后，图片和当前操作始终是视觉焦点。
- **真实的空间层级**：主要表面通过透明度、模糊、边缘高光和阴影建立前后关系。
- **冷暖平衡**：薄荷青负责主操作，天青负责文件与媒体语义，珊瑚色只用于消费、警告等辅助信息。
- **清晰优先**：玻璃不是低对比；正文、边界和交互状态必须在复杂背景上稳定可读。

## 2. 设计原则

1. 玻璃只用于应用壳、主工具面板、浮层等有空间意义的表面。
2. 页面区段保持无框，禁止把每个区段都包装成悬浮卡片。
3. 重复项目可以使用卡片；卡片内部不再嵌套装饰性卡片。
4. 图片内容优先，控件不得覆盖图片的关键检查区域。
5. 所有状态至少通过颜色之外的一种信号表达，例如图标、边框或文字。
6. 动效只解释层级与状态变化，不使用持续漂浮或干扰创作的循环动画。

## 3. 色彩系统

色彩变量定义在 `src/styles/liquid-glass.css`，组件中禁止复制十六进制值。

| Token | 值 | 用途 |
| --- | --- | --- |
| `--bg` | `#070B0D` | 应用底色 |
| `--surface` | `rgba(18, 27, 29, .72)` | 主玻璃表面 |
| `--surface-raised` | `rgba(18, 27, 29, .90)` | 重复卡片与高可读表面 |
| `--field` | `rgba(4, 10, 12, .58)` | 输入、选择器底色 |
| `--line` | `rgba(226, 247, 240, .12)` | 常规边界 |
| `--line-strong` | `rgba(129, 226, 204, .30)` | 悬停与强调边界 |
| `--text` | `#F2FAF7` | 标题与主要内容 |
| `--soft` | `#CAD7D3` | 次级正文 |
| `--muted` | `#9EAFAA` | 辅助说明与元信息 |
| `--accent` | `#75E2C6` | 主操作与选中状态 |
| `--tech-cyan` | `#78D8F1` | 文件、上传、媒体相关状态 |
| `--warm` | `#FF9C7D` | 消耗、提醒等辅助强调 |
| `--danger` | `#FF7F8B` | 破坏性操作与错误 |
| `--success` | `#70D8A9` | 成功与积分收入 |

使用约束：

- 主按钮使用纯色 `--accent`，不在同一视图出现多个争夺注意力的高亮按钮。
- 暖色不是第二主色，只用于语义提示。
- 正文禁止使用低于 `--muted` 的对比度。
- 背景色场只能是大范围、低透明度的光线变化，禁止添加独立渐变球、光斑或装饰性气泡。

## 4. 字体与信息层级

字体栈：`Avenir Next` / `SF Pro Display` / `PingFang SC` / 系统无衬线字体。桌面应用不依赖在线字体，避免离线启动时出现布局跳变。

| 层级 | 建议字号 | 字重 | 用途 |
| --- | ---: | ---: | --- |
| 页面标题 | 22px | 660 | 历史、模板等页面标题 |
| 面板标题 | 18px | 660 | 生成器、结果区、弹窗标题 |
| 卡片标题 | 13-14px | 620-680 | 模板和历史项目 |
| 正文 | 11-13px | 400-600 | 表单、说明、操作 |
| 元信息 | 9-10px | 500-700 | 时间、积分、分类 |

全部文字 `letter-spacing: 0`。标题不得使用随视口变化的字号；紧凑工具面板中禁止使用展示型大标题。

## 5. 材质与层级

### 5.1 一级玻璃

适用：侧栏、生成面板、结果面板、模态框。

- 背景：半透明深色表面加非常轻的方向性高光。
- 模糊：`blur(24px)` 左右，模态框可提高到 `30px`。
- 饱和度：`140%-145%`，保持背景色场的材质感。
- 边框：1px `--line`；浮层可使用 `--line-strong`。
- 圆角：最大 8px。
- 阴影：外部深阴影加 1px 内高光，禁止厚重发光描边。

### 5.2 高可读表面

适用：模板卡片、历史项目、输入控件。

重复内容不使用实时背景模糊，改用更高不透明度的 `--surface-raised`，降低 GPU 开销并保持文字稳定。

### 5.3 无框页面

模板广场和历史页面是内容区段，不使用整页悬浮卡片。页面标题以细分隔线建立结构，卡片只承载独立的模板或历史记录。

## 6. 布局

- 桌面应用壳外边距：12px。
- 侧栏宽度：232px；中等宽度为 204px。
- 主创作区：左侧参数面板 390-440px，右侧结果区占剩余空间。
- 主要间距单位：4 / 8 / 12 / 16 / 20 / 24 / 28px。
- Tauri 默认窗口为 1520x920，最小窗口为 1080x720。
- Web 预览在 900px 以下切换为抽屉导航，在 600px 以下将结果和表单控件改为单列。

固定格式控件必须有稳定尺寸：比例按钮、图标按钮、模板预览和结果网格不能因文字或加载状态改变外框大小。

## 7. 组件规范

### 导航

- 当前项使用薄荷青文字、半透明底和左侧 2px 状态线。
- 导航图标统一使用 `lucide-vue-next`，常规尺寸 16-19px。
- 图标按钮必须提供 `title` 或 `aria-label`。

### 按钮

- 主按钮：明确提交操作，例如“开始生成”“保存设置”。
- 次按钮：可逆的相关操作，例如刷新积分。
- 幽灵按钮：取消、清空或工具操作。
- 纯工具操作优先使用图标按钮，不用带文字的圆角矩形替代熟悉图标。
- 悬停只改变颜色、边界、阴影，不通过明显缩放造成布局跳动。

### 表单

- 输入高度 42px，圆角 7px。
- 聚焦状态使用 1px 薄荷青边界和 3px 低透明度焦点环。
- 单选集合使用分段控制外观，原生 input 继续保留以支持键盘和读屏。
- 范围、开关和复选状态必须保留原生语义。

### 图片与卡片

- 图片使用稳定的 `aspect-ratio` 或固定网格轨道。
- 模板图片必须展示真实效果，不以纯装饰图替代。
- 图片工具在悬停和键盘聚焦时出现，背景使用高对比小型玻璃控件。
- 卡片圆角最大 8px；卡片内部禁止再包同类卡片。

### 弹窗

- 使用清晰标题和关闭图标，遮罩模糊弱于弹窗自身。
- 高度超过视口时只滚动弹窗内容区，页头和操作区保持稳定。
- 新弹窗必须支持 `Escape` 关闭、焦点管理和明确的 `role="dialog"`。现有弹窗可在相关功能改动时逐步补齐。

## 8. 动效

- 常规交互：180ms ease。
- 面板进入：360-420ms，向上 8px 并淡入。
- 模态框：200ms，轻微位移与透明度变化。
- 加载骨架：只在真实等待期间使用。
- 必须遵守 `prefers-reduced-motion: reduce`，禁用非必要动画。

## 9. 可访问性

- 交互元素必须可通过键盘到达，并保留可见焦点环。
- 正文与表面目标对比度至少 4.5:1；大字至少 3:1。
- 不使用颜色作为唯一状态信号。
- 图片提供描述用途的 `alt`；装饰图标使用 `aria-hidden` 或由按钮标签承接语义。
- 支持 `prefers-contrast: more`，提高边界与辅助文本对比度。
- 文本在 320px 宽度下不得溢出按钮、卡片和表单控件。

## 10. 实现约定

- `src/styles/main.css`：基础重置、布局和既有组件结构。
- `src/styles/liquid-glass.css`：设计 tokens、材质、主题覆盖和主题响应式规则。
- 新组件优先复用现有语义类和 tokens；不要新增硬编码主题颜色。
- 只有应用级通用样式进入全局文件，组件私有样式使用 `<style scoped>`。
- 不引入 Tailwind 或新的组件库来实现单个视觉需求。
- 不使用 Emoji 作为功能图标，不手绘已有的 Lucide 图标。

- [ ] 900px 与 390px 宽度下导航、表单、结果区无重叠。
- [ ] 文生图、图生图、模板、历史和所有弹窗均检查过。
- [ ] 所有交互状态包含 hover、focus、disabled 和 loading。
- [ ] 玻璃表面的正文与边界清晰可读。
- [ ] 页面没有装饰性卡片嵌套、渐变球或无功能的说明文字。
